## 2. 分阶段开发过程记录

### Day 1（2026-10-30）：第一阶段 —— 需求分析、架构设计与验收标准冻结

- **阶段目标**：不急于直接堆砌代码，先按规范软件工程流程完成产品需求、页面原型结构、数据库 Schema 与 13 项验收标准设计。
- **本人主导完成的决策与设计**：
  1. **确定核心业务闭环**：围绕大学生备赛与个人项目开发痛点，确立 `学习目标 (Goals) → 项目 (Projects) → 任务 (Tasks) → 学习总览 (Dashboard) → 每周复盘 (Weekly Reviews)` 五步闭环，砍掉第一版不必要的“AI 聊天助手”“拖拽看板”和“多人社区”，确保 2 周内高质量交付。
  2. **制定数据库关联与防误删策略**：决定将 `projects.goal_id` 和 `tasks.project_id` 均设为可空外键，并采用 `ON DELETE SET NULL`，确保删除项目时不会误删学生辛苦积累的历史任务记录。
  3. **强化数据安全与演示可靠性**：
     - 针对多用户隔离需求（`AC-10`），要求在 PostgreSQL RLS 策略中不仅校验 `user_id = auth.uid()`，还必须通过 `EXISTS` 子查询拦截“将任务绑定到他人项目”的越权请求；
     - 针对比赛答辩现场可能存在的网络限制，确定采用“Supabase 云端 + 本地持久化双模式引擎”，内置竞赛生真实背景演示数据。
  4. **确立 13 项量化验收标准（`AC-01` ~ `AC-13`）**：明确了项目完成率计算公式（如 5 项完成 3 项显示 `60%`，0 项显示 `暂无任务`）、同周复盘唯一性（`(user_id, week_start)` Upsert）及 `390px` 移动端适配标准。
