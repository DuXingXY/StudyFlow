# 06 - 架构与技术决策记录 (Architecture Decision Records, ADR)

> **项目名称**：StudyFlow（学程）—— 大学生学习与项目管理平台  
> **文档版本**：v1.0（第一阶段冻结版）  
> **制定日期**：2026-10-30  
> **文档目的**：记录项目在产品范围、技术选型、数据库约束与开发协作模式上的关键决策及取舍理由，作为职业规划大赛答辩与工程复盘的核心依据。

## ADR-01：为什么选择“大学生学习与项目管理平台 (StudyFlow)”作为参赛代表项目？

- **背景**：开发者目前已取得第八届码蹄杯省赛银奖、第十七届蓝桥杯 C/C++ 山东赛区三等奖、传智杯初赛二等奖、2026 团体程序设计天梯赛省三等奖、校园程序设计赛二等奖共 5 项算法竞赛成果，且 GitHub 上已有早期的 Python 余额查询工具小项目。在参加《第四届全国大学生职业规划大赛》（成长赛道）时，职业目标定为**软件开发工程师**。
- **决策**：开发一款能够串联“目标制定 → 项目规划 → 任务执行 → 进度统计 → 每周复盘”的完整 Web 工程项目 **StudyFlow（学程）**。
- **理由**：
  1. **契合个人成长主线**：从单文件、重逻辑的“算法竞赛题”迈向包含需求分析、数据建模、权限隔离、前端工程化与测试验收的“完整软件系统开发”，真实体现向软件开发工程师转型升级的行动（占成长赛道评分的 50% + 20% = 70%）。
  2. **评委友好且自证性强**：相比过于底层的纯命令行工具，学习与项目管理平台不仅能让不同专业背景的评委一眼看懂业务价值，而且系统里管理的正是开发者自己备战竞赛和开发软件项目的真实任务与周复盘。

## ADR-02：前端技术栈选型 —— React + TypeScript + Vite + Tailwind CSS

- **背景**：需要在约 2 周周期内完成高可用、类型安全、桌面与移动端自适应的 Web 应用。
- **决策**：采用 `React 18/19 + TypeScript + Vite + Tailwind CSS + React Router`。
- **理由**：
  1. **TypeScript 强类型约束**：确保数据库实体（`Goal`, `Project`, `Task`, `WeeklyReview`）在数据访问层与 UI 组件之间严格对齐，减少空指针与字段拼写错误。
  2. **Vite 极速构建**：冷启动快、热更新即时，适合快速迭代与现场演示。
  3. **Tailwind CSS 响应式能力**：通过原子化样式与 `sm:` / `md:` / `lg:` 断点，低成本满足桌面端左侧导航与 `390px` 移动端窄屏无溢出适配（`AC-12`）。

## ADR-03：后端与持久化架构 —— Supabase (PostgreSQL + RLS) + 本地持久化双引擎模式

- **背景**：
  - 一方面，项目需要体现真实的数据库建模、外键约束与 PostgreSQL Row Level Security (RLS) 行级安全隔离能力；
  - 另一方面，在比赛学院选拔现场答辩、录屏演示或同学克隆仓库本地试用时，如果强依赖海外 Supabase 云服务网络或必须手动配置 `.env` 密钥才能启动，容易因网络波动或未配环境变量导致演示受阻。
- **决策**：
  1. 完整编写标准的 `supabase/migrations/001_init_studyflow.sql`（含 4 张表、UUID、外键、触发器与完整的 RLS 策略），并提供 `SupabaseRepository` 连接真实云端；
  2. 同时在数据抽象层实现一套 100% 遵循相同业务约束、外键联动、RLS 跨用户拦截逻辑的 `LocalPersistenceRepository`（默认零配置开箱即用，且内置竞赛生真实种子数据与 User A / User B 双账户切换验证器）。
- **理由**：
  - 既保证了数据库与安全架构设计的专业深度（可直接在 Supabase 云端部署运行），又实现了 `npm install && npm run dev` **零外部依赖秒级启动演示**的极佳工程可靠性。

## ADR-04：外键删除策略 —— 为什么删除项目时任务采用 `ON DELETE SET NULL` 而非级联删除？

- **背景**：当用户在项目列表中删除某个项目（`projects`）时，该项目下可能已经积累了多条已完成或进行中的学习任务（`tasks`）。
- **决策**：`tasks.project_id` 外键设置为 `REFERENCES public.projects(id) ON DELETE SET NULL`；同样，`projects.goal_id` 设置为 `REFERENCES public.goals(id) ON DELETE SET NULL`。
- **理由**：
  1. **保护用户学习资产**：大学生的历史已完成任务是周复盘与学习总览统计的重要依据。如果采用 `ON DELETE CASCADE`（级联删除），误删一个项目会导致历史完成的任务记录与完成率统计瞬间归零。
  2. **支持独立任务解耦**：删除项目后，原有任务保留并自动转为“未绑定项目的独立任务”，符合真实学习场景预期。

## ADR-05：周复盘幂等与唯一性设计 —— 为什么采用 `(user_id, week_start)` 联合唯一约束？

- **背景**：学生在同一个自然周内可能会多次打开“每周复盘”页面补充本周成果或调整下周计划。
- **决策**：
  - 所有复盘日期在前端和存储层统一归一化为**所在自然周的周一（ISO Week Monday，`YYYY-MM-DD`）**；
  - 数据库层建立 `UNIQUE (user_id, week_start)` 约束；
  - 保存操作统一使用 **Upsert（存在则更新，不存在则插入）**。
- **理由**：从根源上杜绝同一自然周出现多条重复复盘记录（满足 `AC-08`），保证历史复盘时间线的整洁与确定性。

## ADR-06：功能取舍 —— 为什么第一版不做拖拽看板 (Kanban) 和 AI 聊天助手？

- **背景**：市面上许多大型项目管理软件包含拖拽看板、甘特图或 AI 对话框。
- **决策**：MVP 第一版聚焦**结构化列表 + 表单 + 状态/优先级/日期筛选**，暂缓拖拽看板与内置 AI 聊天。
- **理由**：
  1. **控制工程风险**：拖拽看板在 `390px` 移动端视口上交互体验差且极易引发横向滚动条溢出（违反 `AC-12`）；
  2. **突出核心闭环**：对于职业规划大赛而言，评委更看重核心数据链路（目标 → 项目 → 任务 → 统计 → 复盘）是否扎实、完成率计算是否准确、权限是否安全，而非花哨的外围插件。

## ADR-07：人机协作边界（个人主导设计/测试 vs. AI 辅助实现）

- **背景**：项目使用 AI 编程工具（Codex / Antigravity）辅助加速代码开发，但参赛材料必须真实体现个人工程思考与主导作用。
- **决策**：明确划分职责边界并全程记录在 `07-DEVLOG.md` 中：
  - **开发者本人负责（Product & QA Owner）**：需求定义、业务流程设计、数据表关系与安全边界审定、验收标准（`AC-01`~`AC-13`）制定、逐模块功能测试、Bug 发现与复盘总结；
  - **AI 编程工具负责（Implementation Assistant）**：根据冻结的工程文档生成样板代码、组件结构、样式适配与 SQL 脚手架。
