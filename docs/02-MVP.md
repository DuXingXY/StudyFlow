# 02 - MVP 功能清单与业务规则规范 (MVP Specification)

> **项目名称**：StudyFlow（学程）—— 大学生学习与项目管理平台  
> **文档版本**：v1.0（第一阶段范围冻结版）  
> **制定日期**：2026-10-30  
> **核心原则**：完成真正可用的“目标 → 项目 → 任务 → 总览 → 复盘”完整数据闭环，所有展示数据均源自真实持久化存储，绝不使用静态假数据硬编码充数。

## 2. 各模块功能明细与业务规则

### 2.1 M-01 账户管理与演示支撑 (`Account & Auth`)
1. **用户注册与登录**：
   - 支持邮箱 + 密码（不少于 6 位）注册新账号并登录。
   - 表单需校验邮箱格式与密码长度，认证失败时展示明确的中文错误提示。
2. **会话持久化与路由守卫**：
   - 登录成功后刷新页面或重新打开浏览器，登录状态保持有效。
   - 未登录状态下直接访问 `/dashboard`、`/goals`、`/projects`、`/tasks`、`/reviews` 等受保护路由时，自动重定向至 `/login`。
3. **退出登录**：
   - 侧边栏底部展示当前登录账号信息与“退出登录”按钮，点击后清除会话并跳转回 `/login`。
4. **双模式运行与快速演示账号（工程体验增强）**：
   - 当配置了 `VITE_SUPABASE_URL` 与 `VITE_SUPABASE_ANON_KEY` 时，连接云端 Supabase Auth 与 PostgreSQL 数据库。
   - 当未配置云端环境变量或处于离线答辩环境时，自动启用**本地持久化隔离引擎（Local Persistence Mode）**，并提供一键切换/初始化“竞赛生演练账号（User A）”与“隔离测试空白账号（User B）”的能力，方便现场演示 `AC-10（用户数据隔离）` 与完整业务流程。

### 2.2 M-02 学习总览 (`Dashboard`)
1. **顶部核心指标卡片（4 项实时统计）**：
   - **今日待办任务数**：`status != 'done'` 且（`planned_date == 今天` 或 `due_date == 今天`）的任务数量。
   - **逾期未完成任务数**：`status != 'done'` 且 `due_date < 今天` 的任务数量（存在逾期时红色高亮警示）。
   - **进行中项目数**：`status == 'active'` 的项目数量。
   - **任务总完成率**：当前用户已完成任务数 / 总任务数（无任务时显示 `0%` 或 `暂无任务`）。
2. **今日聚焦任务列表**：
   - 展示今日计划执行（`planned_date == 今天`）、今日截止（`due_date == 今天`）以及已逾期未完成的任务。
   - 支持在总览页直接勾选/切换任务状态（`todo` ↔ `doing` ↔ `done`），状态变更后指标卡片与关联项目进度实时同步更新。
3. **进行中项目进度概览**：
   - 列出当前状态为“进行中 (`active`)”的项目，展示项目名称、所属学习目标标签、任务完成比例（如 `3 / 5 已完成`）与可视化进度条（如 `60%`），点击可直达 `/projects/:id` 详情页。

---

### 2.3 M-03 学习目标管理 (`Goals`)
1. **字段规范**：
   - `title`（必填，1~100 字符）：目标名称，如“备战蓝桥杯与码蹄杯程序设计省赛”或“完成向软件开发工程师的工程化转型”。
   - `description`（选填，最多 500 字符）：目标背景、衡量标准或阶段说明。
   - `target_date`（选填，日期类型 `YYYY-MM-DD`）：期望达成日期。
   - `status`（必选枚举）：
     - `active`（进行中，默认）
     - `completed`（已完成）
     - `paused`（已暂停）
2. **核心交互**：
   - 支持新建目标、编辑目标内容、快捷切换目标状态、删除目标。
   - 每个目标卡片展示其下关联的项目数量及关联项目列表入口。
   - **删除保护规则**：删除学习目标时，不删除其下关联的项目，而是将对应项目的 `goal_id` 自动置为 `null`（转为独立项目）。

---

### 2.4 M-04 项目管理与项目详情 (`Projects & Project Detail`)
1. **字段规范**：
   - `name`（必填，1~100 字符）：项目名称，如“StudyFlow 大学生学习与项目管理平台 MVP”。
   - `goal_id`（选填，UUID 外键）：关联的学习目标 ID，允许为空（即独立项目）。
   - `description`（选填，最多 500 字符）：项目简介、技术栈或交付目标。
   - `due_date`（选填，日期类型 `YYYY-MM-DD`）：项目计划截止日期。
   - `status`（必选枚举）：
     - `active`（进行中，默认）
     - `completed`（已完成）
     - `on_hold`（已搁置/暂停）
2. **项目完成率计算规则（核心验收点 `AC-06`）**：
   - 设该项目下关联的任务总数为 $N_{\text{total}}$，其中 `status == 'done'` 的任务数为 $N_{\text{done}}$：
     - 当 $N_{\text{total}} = 0$ 时：进度显示为 **`暂无任务`**（进度条宽度为 `0%`）；
     - 当 $N_{\text{total}} > 0$ 时：完成率计算公式为 $\text{ round}\left(\frac{N_{\text{done}}}{N_{\text{total}}} \times 100\right)\%$。例如共有 5 个任务且完成 3 个时，准确显示 **`60%`**（附带 `3/5 任务已完成` 文字说明）。
3. **项目详情页 (`/projects/:id`)**：
   - 展示项目基本信息、关联的学习目标、截止日期与当前进度条。
   - 展示归属于该项目的所有任务列表，支持在详情页内**直接为该项目新增任务**、切换任务状态、编辑或删除任务，操作后项目进度条实时重算。
4. **删除项目保留任务规则（数据库安全约定）**：
   - 删除项目时，必须弹窗二次确认，并明确提示用户：**“删除项目后，该项目下的原有任务将被保留并转为独立任务，不会丢失学习记录。”**
   - 底层通过外键 `ON DELETE SET NULL` 将原属该项目的任务 `project_id` 置空。

---

### 2.5 M-05 任务中心 (`Tasks`)
1. **字段规范**：
   - `title`（必填，1~150 字符）：任务标题，如“编写 StudyFlow PostgreSQL RLS 安全策略脚本”。
   - `project_id`（选填，UUID 外键）：所属项目 ID，允许为空（支持日常独立任务）。
   - `status`（必选枚举）：
     - `todo`（待办，默认）
     - `doing`（进行中）
     - `done`（已完成）
   - `priority`（必选枚举）：
     - `low`（低优先级）
     - `medium`（中优先级，默认）
     - `high`（高优先级）
   - `planned_date`（选填，`YYYY-MM-DD`）：计划执行日期（用于排入“今日任务”）。
   - `due_date`（选填，`YYYY-MM-DD`）：最后截止日期（用于判断逾期）。
   - `completed_at`（系统自动维护，时间戳）：当状态切换为 `done` 时自动记录当前时间；从 `done` 切回 `todo` 或 `doing` 时自动清空为 `null`。
2. **逾期判定与提醒规则（核心验收点 `AC-05`）**：
   - 若任务满足 `status != 'done'` 且 `due_date < 当前本地日期 (YYYY-MM-DD)`，则判定为**已逾期（Overdue）**。
   - 已逾期任务在任务列表、项目详情及学习总览中均显示醒目的红色 **`已逾期`** 标签及截止日期高亮提醒。
3. **筛选与排序功能**：
   - **快捷视图切换**：`全部任务` | `今日计划/今日截止` | `已逾期` | `待办 (todo)` | `进行中 (doing)` | `已完成 (done)`。
   - **多维过滤**：按所属项目筛选（含“未关联项目的独立任务”）、按优先级筛选（`high` / `medium` / `low`）、按关键词搜索任务标题。

---

### 2.6 M-06 每周复盘 (`Weekly Reviews`)
1. **自然周计算与唯一性约束（核心验收点 `AC-08`）**：
   - 系统以每周一作为自然周起始日 `week_start`（格式 `YYYY-MM-DD`，默认自动计算当前日期所在周的周一，也支持用户选择其他周对应的日期并自动归一化到该周周一）。
   - **唯一性规则**：每位用户在每个自然周（`user_id + week_start`）**最多只能有一条复盘记录**。
   - 当用户选择已存在复盘记录的自然周时，表单自动回填该周已有内容；点击保存时执行 **Upsert（更新原记录）**，绝不产生同一周的两条重复记录。
2. **字段规范**：
   - `week_start`（必填，归一化为周一日期 `YYYY-MM-DD`）：复盘周期（界面同时友好展示周区间，如 `2026-10-26 ~ 2026-11-01`）。
   - `achievements`（必填）：本周核心成果与收获。
   - `problems`（必填）：本周遇到的困难、暴露的知识/工程短板。
   - `next_plan`（必填）：下周具体改进计划与重点任务。
3. **复盘辅助统计**：
   - 在编写当周复盘时，页面侧边自动汇总展示本周已完成任务数量与已完成任务清单参考，帮助用户做到“有据可依”地复盘。

## 3. 异常与边界处理规范（对应 `AC-11`）

| 场景类别 | 触发条件 | 系统标准响应行为 |
| :--- | :--- | :--- |
| **空数据状态 (Empty State)** | 新注册用户或筛选结果为空时（无目标、无项目、无任务、无复盘） | 展示结构化的空状态插画/图标、引导文案及快捷创建按钮（如“暂无学习目标，点击右上角创建第一个目标”） |
| **表单校验拦截 (Validation)** | 标题为空、纯空格、超出字数限制、或截止日期格式非法 | 阻止提交，在对应输入框下方显示清晰的中文错误提示（如“任务标题不能为空”） |
| **网络/接口异常 (Error State)** | 数据库请求失败、断网或无权限操作 | 顶部或操作区弹出错误提示框（Toast / Banner），保留用户已填写的表单内容不丢失，允许重试 |
| **非法外键拦截 (Security)** | 尝试将任务关联到非本人项目，或将项目关联到非本人目标 | 数据库层 RLS `WITH CHECK` 与应用层双重拦截，拒绝写入并提示权限错误 |
