# 05 - 验收标准与测试规范 (Acceptance Criteria & Test Plan)

> **项目名称**：StudyFlow（学程）—— 大学生学习与项目管理平台  
> **文档版本**：v1.0（第一阶段冻结版）  
> **制定日期**：2026-10-30  
> **验收原则**：代码编写完成不代表项目完成，必须逐条通过以下 13 项验收标准（`AC-01` ~ `AC-13`）并保留测试证据，方可认定 MVP 交付达标。

## 2. 逐项详细验收用例 (Test Cases)

### AC-01：账户认证与路由拦截
- **前置条件**：浏览器处于未登录状态（清除会话或点击退出登录）。
- **测试步骤**：
  1. 在地址栏直接访问 `/dashboard`、`/goals`、`/projects`、`/tasks`、`/reviews`；
  2. 在 `/login` 页面输入新邮箱与密码（`>= 6` 位）完成注册或登录；
  3. 登录成功后进入 `/dashboard`，点击左下角“退出登录”。
- **预期结果**：
  1. 未登录访问任意业务路由均立即被重定向至 `/login`；
  2. 注册/登录成功后自动跳转至 `/dashboard`，侧边栏正确展示当前登录用户邮箱；
  3. 退出登录后会话清除，再次回退或访问 `/dashboard` 被拦截回 `/login`。

### AC-02：学习目标生命周期管理
- **测试步骤**：
  1. 进入 `/goals`，点击“新建学习目标”，填写标题“备战程序设计竞赛省赛”、描述与目标日期并保存；
  2. 编辑该目标标题或描述并保存；
  3. 将该目标状态依次切换为“已完成 (`completed`)”与“已暂停 (`paused`)”；
  4. 创建一个测试目标并点击删除。
- **预期结果**：列表实时更新，状态徽章与筛选器准确响应，删除后目标从数据库中移除（其下原本关联的项目 `goal_id` 自动变为 `null` 而不被误删）。

### AC-03：项目管理与目标关联
- **测试步骤**：
  1. 进入 `/projects`，新建项目 A 并选择关联“从程序设计竞赛向软件开发工程师转型”目标；
  2. 新建项目 B 且不选择关联目标（作为独立项目）；
  3. 点击项目 A 卡片进入 `/projects/:id` 详情页。
- **预期结果**：项目 A 显示关联目标标签，项目 B 显示“独立项目”；点击详情可查看项目完整信息及专属子任务面板。

### AC-04：任务管理与“删项目保任务”验证
- **测试步骤**：
  1. 在 `/tasks` 或项目详情页新增任务，编辑任务标题、优先级（高/中/低）与所属项目；
  2. 切换任务状态：`待办 (todo)` → `进行中 (doing)` → `已完成 (done)`；
  3. 创建一个包含 2 条任务的测试项目，随后删除该测试项目，再回到 `/tasks` 查看原属该项目的 2 条任务。
- **预期结果**：
  - 状态切换为 `done` 时自动记录 `completed_at`，切回未完成时清空 `completed_at`；
  - 删除测试项目后，原有的 2 条任务依然完好保存在 `/tasks` 中，且其所属项目显示为“未关联项目（独立任务）”。

### AC-05：计划日期与逾期高亮提醒
- **测试步骤**：
  1. 创建一条状态为 `todo` 的任务，将其 `due_date` 设置为昨天（早于今天）；
  2. 创建一条状态为 `todo` 的任务，将其 `planned_date` 设置为今天；
  3. 将第 1 条逾期任务的状态切换为 `done`。
- **预期结果**：
  - 未完成且 `due_date < 今天` 的任务在 `/tasks`、`/projects/:id` 和 `/dashboard` 中均显示红色 **`已逾期`** 标签，且总览页“逾期未完成”计数 `+1`；
  - 当该任务标记为 `done` 后，红色逾期警告立即消除，逾期计数 `-1`。

### AC-06：项目完成率精确计算
- **测试步骤**：
  1. 查看一个没有任何任务的新建项目；
  2. 在某项目下确保共有 5 个子任务，将其中 3 个标记为 `done`，另外 2 个保持 `todo` 或 `doing`。
- **预期结果**：
  - 无任务的项目显示 **`暂无任务`**（不出现 `NaN%` 或除零错误）；
  - 5 个任务完成 3 个的项目，在项目列表页、项目详情页及学习总览页中均准确显示 **`60%`**（`3/5 已完成`）。

### AC-07：学习总览 (Dashboard) 真实数据联动
- **测试步骤**：在 `/tasks` 中新增一条 `planned_date` 为今天的待办任务，或将某个进行中项目的子任务勾选完成，随后切回 `/dashboard`。
- **预期结果**：`/dashboard` 中的今日待办数量、今日任务列表、项目进度百分比与总完成率均与真实数据库状态完全一致。

### AC-08：每周复盘自然周唯一性 (Upsert)
- **测试步骤**：
  1. 进入 `/reviews`，选择当前自然周（如周一 `2026-10-26`），填写成果、问题与下周计划，点击保存；
  2. 修改“下周计划”内容，在同一自然周下再次点击保存；
  3. 检查历史复盘列表及数据库表记录数。
- **预期结果**：第二次保存直接更新该周原有记录，历史复盘列表中 `2026-10-26` 这一周**只有唯一的一条记录**，且内容为最新修改版。

### AC-09：数据持久化验证
- **测试步骤**：完成目标、项目、任务、周复盘的新增与修改后，按 `F5` 强制刷新浏览器页面，再退出登录并重新登录同一账号。
- **预期结果**：所有已保存的数据、状态与统计进度 100% 完整保留。

### AC-10：多用户数据隔离与跨用户外键防护
- **测试步骤**：
  1. 登录用户 A，记录其下的目标、项目（记下某个 `project_id`）与任务数据；
  2. 退出并登录用户 B，查看 `/dashboard`、`/goals`、`/projects`、`/tasks`、`/reviews`，并尝试直接访问 `/projects/<用户A的project_id>`；
  3. 尝试通过数据接口以用户 B 身份创建一条 `project_id = <用户A的project_id>` 的任务。
- **预期结果**：
  - 用户 B 完全看不到用户 A 的任何数据；
  - 访问用户 A 的项目详情提示“项目不存在或无权访问”；
  - 跨用户关联 `project_id` 或 `goal_id` 的写入请求被 RLS / 数据安全层直接拒绝拦截。

### AC-11：异常与边界处理
- **测试步骤**：
  1. 登录一个全新空白账号查看各页面空状态；
  2. 提交空白标题的目标/项目/任务/复盘表单；
  3. 模拟接口异常或非法输入。
- **预期结果**：空白页展示友好的引导占位图与新建入口；非法输入显示明确的字段校验提示；无白屏崩溃或未捕获控制台异常。

### AC-12：`390px` 移动端适配验证
- **测试步骤**：使用浏览器开发者工具（或自动化浏览器测试）将视口宽度设为 `390px × 844px`（iPhone 14 尺寸），依次浏览并操作全部 7 个路由页面。
- **预期结果**：`document.documentElement.scrollWidth <= 390`，无整体横向滚动条溢出；移动端顶部导航菜单可正常展开切换页面，模态框与表单可正常输入提交。

### AC-13：工程构建、README 与完整演示交付
- **测试步骤**：执行 `npm run build` 检查 TypeScript 编译与生产包构建，按照 `README.md` 指引启动项目并走查完整演示脚本。
- **预期结果**：零编译报错、零类型错误，文档齐全，3 分钟内可完整演示“目标 → 项目 → 任务 → 统计 → 复盘 → 用户隔离”全链路。
